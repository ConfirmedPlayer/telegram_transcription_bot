# Развёртывание на сервере

Гайд для бота, который работает через Docker Compose (`docker-compose.yml` в корне репозитория).
Есть два сценария:

- **[Обновление](#обновление-работающего-бота)** — бот уже крутится на сервере, нужно выкатить сводки и исправление утечки токена.
- **[Первая установка](#первая-установка)** — на сервере бота ещё нет.

Команды ниже — для Linux-сервера с Docker Engine и плагином Compose (`docker compose`). Если на сервере
старый `docker-compose` (через дефис), команды те же, просто пишутся через дефис.

---

## Что понадобится заранее

Всё это делается в браузере и в Telegram, до захода на сервер.

1. **Ключ Cerebras** (основной провайдер сводок): [cloud.cerebras.ai](https://cloud.cerebras.ai) → API Keys → создать ключ.
2. **Ключ Groq** (резервный провайдер): [console.groq.com](https://console.groq.com) → API Keys → создать ключ.
3. **В консоли Groq**: Settings → Data Controls → включить **Zero Data Retention**.
4. **Доступ к @BotFather** в Telegram — понадобится, чтобы выпустить новый токен бота (см. шаг 5 обновления).

Оба провайдера бесплатны и без банковской карты. Сводки работают и с одним ключом.

## Обновление работающего бота

Порядок шагов выбран так, чтобы бот простаивал только на время перезапуска контейнера (секунды), а не на время сборки.

### 1. Отправить код на GitHub (на своём компьютере)

```bash
git push origin main
```

> Если код на сервер попадает не через git, а копированием — пропустите этот шаг и в шаге 2 используйте
> `rsync` (см. [Без git](#без-git)).

### 2. Забрать код на сервере

```bash
cd ~/telegram_transcription_bot    # ваш путь к боту на сервере
git pull
```

Работающий бот от этого не останавливается: он запущен из старого образа.

### 3. Добавить ключи в `.env`

Откройте `.env` (например, `nano .env`) и допишите две строки:

```env
LLM_PRIMARY_API_KEY=ключ_cerebras
LLM_FALLBACK_API_KEY=ключ_groq
```

`BOT_TOKEN` пока **не трогайте** — его заменим в шаге 5. Остальные настройки сводок необязательны,
значения по умолчанию описаны в `config/config.py`.

Заодно закройте файл от чужих глаз:

```bash
chmod 600 .env
```

### 4. Собрать новый образ и проверить ключи

Сборка идёт, пока старый бот продолжает работать:

```bash
docker compose build
```

Предупреждение `the attribute 'version' is obsolete` — безвредное, не обращайте на него внимания.

Теперь проверка ключей и моделей **из самого сервера** — отдельным одноразовым контейнером
на новом образе, работающий бот не затрагивается:

```bash
docker compose run --rm bot python -c "
import asyncio
from services import llm
async def main():
    for p in llm.configured_providers():
        try:
            text = await llm.call_provider(p, [{'role': 'user', 'content': 'Ответь одним словом: работает'}], 50, 15)
            print(p.name, 'OK:', text[:60])
        except Exception as e:
            print(p.name, 'ОШИБКА:', type(e).__name__, str(e)[:120])
asyncio.run(main())
"
```

Ожидается:

```
api.cerebras.ai OK: Работает
api.groq.com OK: Работает
```

Если вместо `OK` ошибка:

| Ошибка | Причина | Что делать |
|---|---|---|
| `AuthenticationError` | неверный ключ | перепроверить ключ в `.env`, без пробелов и кавычек |
| `NotFoundError` | модель недоступна на вашем аккаунте | в панели провайдера посмотреть доступные модели, задать `LLM_PRIMARY_MODEL` / `LLM_FALLBACK_MODEL` в `.env` |
| `PermissionDeniedError` | провайдер не обслуживает IP сервера (гео-ограничения) | проверить с другого сервера; если блокирует только один провайдер — сводки будут идти через второй |
| `APIConnectionError`, `APITimeoutError` | сервер не достучался до провайдера | проверить исходящий доступ в интернет и файрвол |
| `OK:` с пустым текстом | модель тратит бюджет на рассуждение | проверить, что в `.env` не переопределены `LLM_*_EXTRA` |

Идите дальше, только когда хотя бы один провайдер отвечает `OK`. Если ни один не отвечает,
бот всё равно будет работать — просто без сводок, как раньше.

### 5. Выпустить новый токен бота

До исправления бот писал токен в лог при каждом сообщении, так что **старый токен уже лежит
в логах** (`docker logs` хранит до 30 МБ истории). Его нужно считать скомпрометированным.

1. В Telegram откройте **@BotFather** → `/revoke` → выберите бота.
   С этого момента старый бот перестаёт работать — начинается простой.
2. Сразу впишите новый токен в `.env` вместо старого значения `BOT_TOKEN=`.

### 6. Подготовить каталог логов

Бот в контейнере работает от пользователя с uid 1000 и пишет лог в смонтированный каталог `./logs`.
Если Docker когда-то создал этот каталог сам, он принадлежит root, и бот туда писать не сможет:

```bash
mkdir -p logs
sudo chown -R 1000:1000 logs
```

Без этого бот не упадёт, а будет писать лог внутрь контейнера, где он пропадает при каждом перезапуске.

### 7. Перезапустить бота на новом образе

```bash
docker compose up -d --force-recreate
```

`--force-recreate` гарантирует, что контейнер подхватит новый `.env` и новый образ.
Простой заканчивается, как только команда отработала.

### 8. Проверить, что всё работает

Контейнер запущен и не перезапускается по кругу:

```bash
docker compose ps
```

В логе есть запуск бота и нет ошибок:

```bash
docker compose logs --tail 30 bot
```

Ищите строки `Starting bot...` и `Run polling for bot`. Если контейнер перезапускается по кругу:
`TelegramUnauthorizedError` — в `.env` старый или чужой `BOT_TOKEN`; `TokenValidationError` — токен
вставлен с ошибкой (лишний пробел, кавычки, обрезан).

Лог пишется в смонтированный каталог:

```bash
ls -l logs/
```

Токен больше не попадает в логи. Команда берёт секретную часть токена из `.env` и ищет её в обоих
логах — оба числа должны быть `0`:

```bash
SECRET=$(grep '^BOT_TOKEN=' .env | cut -d: -f2); grep -cF "$SECRET" logs/bot.log; docker compose logs bot 2>&1 | grep -cF "$SECRET"
```

### 9. Подключить бота к группе

1. Добавьте бота в группу **администратором** (права можно оставить минимальными).
   Без этого Telegram не показывает боту сообщения участников — бот будет молчать.
2. Предупредите участников, что голосовые расшифровываются и отправляются во внешние сервисы
   (Deepgram, Cerebras, Groq).
3. Отправьте голосовое на 1–2 минуты. Должны прийти два ответа на него: сначала
   «**Краткое содержание этого голосового сообщения:**», затем «**Расшифровка голосового сообщения:**».
4. Команда `/status` покажет, что бот помнит разговор.

> Альтернатива правам администратора — отключить privacy mode в @BotFather (`/setprivacy` → Disable).
> Но тогда бота нужно **удалить из группы и добавить заново**, иначе настройка не применится.

Полный чек-лист проверки — в задаче 10 плана
[`docs/superpowers/plans/2026-09-18-summary-memory.md`](superpowers/plans/2026-09-18-summary-memory.md).

## Первая установка

### 1. Docker

Установите Docker Engine и плагин Compose по официальной инструкции для вашего дистрибутива:
[docs.docker.com/engine/install](https://docs.docker.com/engine/install/). Проверка:

```bash
docker compose version
```

### 2. Код

```bash
git clone https://github.com/ConfirmedPlayer/telegram_transcription_bot.git
cd telegram_transcription_bot
```

Если репозиторий приватный, понадобится вход в GitHub (токен доступа или SSH-ключ).

### 3. `.env`

Создайте файл `.env` в корне репозитория:

```env
BOT_TOKEN=токен_от_BotFather
DEEPGRAM_API_KEY=ключ_deepgram
ANTHROPIC_API_KEY=
LLM_PRIMARY_API_KEY=ключ_cerebras
LLM_FALLBACK_API_KEY=ключ_groq
```

```bash
chmod 600 .env
```

`ANTHROPIC_API_KEY` можно оставить пустым: стили Anthropic в боте сейчас отключены.

### 4. Сборка, проверка ключей, запуск

Дальше — те же шаги, что и при обновлении:
[4. сборка и проверка ключей](#4-собрать-новый-образ-и-проверить-ключи),
[6. каталог логов](#6-подготовить-каталог-логов),
затем запуск:

```bash
docker compose up -d
```

и [8. проверка](#8-проверить-что-всё-работает), [9. подключение к группе](#9-подключить-бота-к-группе).
Шаг 5 (новый токен) при первой установке не нужен.

## Если что-то пошло не так

### Сводки мешают или ведут себя странно

Сводки выключаются без отката кода: очистите оба ключа в `.env`

```env
LLM_PRIMARY_API_KEY=
LLM_FALLBACK_API_KEY=
```

и перезапустите:

```bash
docker compose up -d --force-recreate
```

Бот продолжит присылать расшифровки, как раньше.

### Сводки не приходят

Все сообщения о сводках в логе начинаются со слова «Сводка»:

```bash
docker compose logs bot 2>&1 | grep "Сводка"
```

| В логе | Что значит |
|---|---|
| `отклонил запрос — проверьте ключ или имя модели` | неверный ключ или модель — прогнать проверку из шага 4 |
| `не ответил за … с` | провайдер медлит; сводка пропущена, расшифровка пришла |
| `не осталось времени на попытку` | основной провайдер съел почти весь бюджет в 15 секунд, на резервный не хватило |
| `вернул пустой ответ` | модель ничего не написала — см. таблицу в шаге 4 |
| `ошибка …: Error code: 429` | исчерпан лимит бесплатного тарифа; сводки вернутся после его сброса |
| `Сводка пропущена: в этом чате ещё строится предыдущая` | несколько голосовых пришли одновременно — это нормально, реплика учтётся в следующей сводке |

Если записей «Сводка» нет совсем — сообщение было короче 100 слов (порог `SUMMARY_MIN_WORDS`)
или ни один ключ не задан.

### Бот не отвечает в группе

Почти всегда это privacy mode: бот не администратор. См. [шаг 9](#9-подключить-бота-к-группе).

### В логе «Нет прав на запись в logs/»

Выполните [шаг 6](#6-подготовить-каталог-логов) и перезапустите контейнер.

### Полный откат на версию до сводок

Последний коммит до изменений — `c2ba3f1`.

```bash
git checkout c2ba3f1
docker compose up -d --build --force-recreate
```

Вернуться обратно:

```bash
git checkout main
docker compose up -d --build --force-recreate
```

> Старая версия снова пишет токен в лог. Откатывайтесь только на время и выпускайте новый токен
> после возврата на `main`.

## Без git

Если код на сервер копируется вручную, с вашего компьютера:

```bash
rsync -av --exclude .git --exclude .venv --exclude logs --exclude .env ./ user@server:~/telegram_transcription_bot/
```

`.env` и `logs` исключены намеренно: на сервере свои. Дальше — с [шага 3](#3-добавить-ключи-в-env).

## Без Docker

Бот можно запустить и напрямую, но нужен **Python 3.10 или новее** (на 3.9 не ставятся `aiogram` и `openai`):

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

Для постоянной работы такой запуск надо обернуть в systemd-сервис — Docker Compose с `restart: always`
делает это за вас, поэтому основной путь в этом гайде — через Docker.
